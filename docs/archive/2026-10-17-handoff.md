## Active service

The browser runs against the Python agent service. Start it from the repository root:
`server/.venv/Scripts/python.exe scripts/start-agent.py --origin https://hp.taile8e695.ts.net`.
Use `server/.venv/bin/python` on macOS/Linux. The launcher enables execution and
creates/reuses a diagnostic token without printing it. Browser access is automatic:
direct localhost or the launcher's own Tailscale user identity through Serve.
The SQLite database and worker lock are
under server/data. Python and Expo need restarting after reboot; no OS startup task
has been installed.

The HP serves Expo on 8081 and Python on loopback:8000. Tailscale routes `/` to Expo
and `/agent` to Python. Ollama stays on 11434. The old proxy on 11435 is stopped, its
`/llm` route removed, and the obsolete proxy/browser-harness source deleted.

## Behavior

Python owns context, model streaming, complete tool loops, and persistent history.
The calculator runs on Python. Location, clock/timezone, and device context are
credential-bound requests to the requesting client. Device requests expire; permission
failure is reported rather than replaced with a fabricated reading.

The UI can stop a request, dismiss restart review, and copy a failed request into a
draft for explicit retry. Cancellation does not delete history or replay tools.
Every device opens one shared chat, with no conversation tabs or new-chat control.
Browser history import previews kinds and appends to that shared chat
with a stable import ID. Original browser history and unfinished legacy recovery data
are preserved. Old pending prompts may be copied into a draft, never auto-run.

## Checks and limitations

See README.md for test commands, server/EXECUTION.md for operations, and
TECHNICAL_DEBT.md for remaining work. Live tests verified a full calculator loop
while the browser was away, a device-clock round trip, and authenticated Tailscale
inference. Physical-phone permissions and remote Mac inference remain untested.

Native llama.rn inference is preserved but deferred. The native build previously ran
in an Android emulator. Use the Windows-native Android toolchain and android-build.ps1
for that path, not mixed WSL/Windows tools; its local SDK/JDK paths are machine-specific.
The active browser path does not require Android or Xcode tooling.
